# FramePair 跨平台技术方案

## 目标与边界

FramePair 包含照片浏览和配对清理两个模块。照片浏览把同一路径、同名的 JPG 与 RAW 组织成逻辑照片；配对清理内部同时承载配对清理和评分同步任务。配对清理将人工筛选结果统一转换为参考键集合，再按照相对子目录与文件名主体判断 RAW 是否保留；评分同步则在只读计划确认后，把工作评分写入启用的 XMP/JPG 元数据目标。

桌面版主动改变四项危险行为：

- 不再扫描 RAW 目录中的任意文件，只处理明确扩展名。
- 不再直接永久删除，只允许系统回收站/废纸篓或应用隔离区。
- 不再边扫描边删除，先生成稳定计划，再审核并重新校验后执行。
- 反向 JPG 审计只生成只读计划，后端不授予清理权限。

## 技术栈

| 层级 | 技术 | 职责 |
|---|---|---|
| 桌面壳 | Tauri 2 | 窗口、IPC、平台打包、能力权限 |
| 前端 | React + TypeScript + Vite | 照片网格、单张预览、评分、目录配置、审核和状态反馈 |
| 核心 | Rust | 照片索引、评分存储、编辑器发现、缩略图、文件遍历、匹配键和路径边界 |
| 图片 | `image` | JPEG 解码、EXIF 方向应用、缩放与 JPEG 缓存编码 |
| 元数据 | `quick-xml` + 结构化 JPEG 段处理 | 有界读取和保留式更新 XMP Rating，不解码或重编码图片 |
| 清理 | `trash` + `std::fs::rename` | 系统回收站或同卷隔离区 |
| 发行 | GitHub Actions + tauri-action | 各操作系统原生 runner 构建安装包 |

Tauri 在 Windows 使用 WebView2，在 macOS 使用 WKWebView。两端共享产品结构与状态模型，但字体、系统目录选择器、窗口装饰和回收站行为由宿主平台提供。

## 核心数据流

照片浏览：

```text
选择照片目录
  -> Rust 规范化根目录并递归读取 JPG/JPEG 与 RAW 白名单
  -> 按相对路径和文件名主体聚合为逻辑照片
  -> React 按需请求当前可见项的网格缩略图，并受控并发预加载全部单张预览
  -> Rust 校验相对路径，应用 EXIF 方向并限制最长边
  -> 写入应用缓存目录并通过二进制 IPC 返回 JPEG
  -> 网格或单张查看器渲染，原始照片保持只读
```

评分与外部编辑：

```text
0-5 星或数字快捷键
  -> React 乐观更新当前评分与筛选结果
  -> Rust 重新校验照片根目录、相对路径和 JPG/RAW 白名单
  -> 在应用数据目录通过临时文件同步并替换 photo-ratings.json，不修改照片/XMP
  -> 外部编辑时重新发现标准安装目录中的 Adobe 应用并匹配编辑器 ID
  -> 再次校验照片路径；配对照片优先把 RAW 交给编辑器
```

评分同步：

```text
当前照片或照片根目录
  -> Rust 聚合 FramePair、JPG 内嵌 XMP 与 RAW XMP 评分
  -> 应用冲突策略并生成一次性只读计划
  -> React 展示来源、工作评分、目标、冲突与不可执行原因
  -> 用户确认手动执行，或 FramePair 评分保存成功后触发自动同步
  -> Rust 复验根目录、目标身份、符号链接和文件快照
  -> 同目录临时文件同步落盘并替换 XMP/JPG 元数据
  -> 单目标失败独立记录；自动同步失败写入待处理状态
```

配对清理：

```text
选择参考源和 RAW 根目录
  -> Rust 规范化路径并验证来源类型
  -> 目录/清单/XMP 统一建立 HashMap<匹配键, 参考记录>
  -> RAW 侧扫描固定白名单格式和 XMP
  -> 生成 Matched/Unmatched 只读计划
  -> React 展示、过滤和选择
  -> 用户确认
  -> Rust 重验相对路径/扩展名/大小/修改时间
  -> 系统回收站，或 .framepair-quarantine/<operation-id>/
  -> JSONL 操作日志/隔离恢复清单
  -> 自动重新扫描
```

匹配键由相对路径去掉最后一个扩展名后得到。例如：

```text
RAW/20260712/DSC_0128.CR3 -> 20260712/DSC_0128
JPG/20260712/DSC_0128.JPG -> 20260712/DSC_0128
```

默认对匹配键做大小写折叠，以保持 Windows 与常见 macOS 文件系统上的一致体验。严格大小写模式由用户显式启用。

## 可信格式策略

前端不再发送扩展名白名单。Rust 固定支持 JPG/JPEG、12 种 RAW 和 XMP，并在扫描、清理候选校验和执行前复验中复用同一策略。即使前端被篡改，也不能授权处理其他扩展名。

XMP 同时支持 `photo.xmp` 与 `photo.NEF.xmp` 两种命名。XMP Rating 使用流式 XML 解析，文件上限为 4 MiB；解析器必须读到 XML 末尾后才接受评分。

## 共享照片组与评分来源

照片浏览与后续配对清理共用照片组模型。照片组 ID 由相对路径去掉最后一个媒体扩展名并折叠大小写得到；JPG、RAW、`photo.xmp` 与 `photo.RAW.xmp` 仍以各自精确相对路径保存在成员列表中，不因分组而丢失真实文件身份、大小或修改时间。

评分状态分别记录三类来源：

- `framePair`：FramePair 自己的 0-5 星评分，存储在应用数据目录。
- `jpegMetadata`：从 JPG 内嵌 XMP 只读提取的评分。
- `rawXmp`：从 RAW 对应 XMP 旁车文件只读提取的评分。

`framePair` 仍是照片浏览、筛选和旧版 `rating` 字段使用的工作评分。手动同步必须先生成一次性只读计划；自动同步只会在 FramePair 评分成功保存后运行，失败不会回滚已保存评分，也不会触发移动、复制、清理或其他文件操作。设置和待处理项保存在版本化的 `rating-sync.json` 中。

默认目标只有 RAW XMP，RAW 原文件永不修改。新旁车统一写为 `photo.xmp`；如果同一照片组同时存在 `photo.xmp` 和 `photo.RAW.xmp` 等多个可写候选，则作为硬冲突拒绝执行。JPG 内嵌评分默认关闭，必须由用户启用并再次确认；写入时只替换或插入 XMP APP1 段，保留 EXIF、其他 APP 段、扫描数据和像素内容。

非空来源不一致、重复目标、XMP/JPEG 元数据损坏、符号链接、路径越界、执行前快照变化或暂不支持的 `-1` 拒绝标记都会按照片组阻止写入。冲突策略可选不覆盖、FramePair 优先、外部优先或取较高评分，但不能绕过路径、格式与快照安全校验。

## 隔离与恢复

隔离区固定在 RAW 根目录的 `.framepair-quarantine` 下，因此 `rename` 保持同一文件系统内移动。扫描器明确排除该目录。每次成功移动都会追加并同步 `manifest.jsonl`；记录失败时立即尝试回滚。

恢复命令只接受 RAW 根目录与操作 ID，不接受前端提供的任意 manifest 路径。恢复前校验操作目录不是符号链接、隔离文件仍符合快照、目标父目录没有越界且原位置不存在同名文件。成功恢复后追加 `restored.jsonl`，应用重启后仍可计算历史状态。

## 扫描方向

- `cleanupRaw`：遍历 RAW 并查询参考键，未配对 RAW/XMP 可以进入清理计划。
- `auditReference`：遍历 JPG 并查询 RAW 键，只允许目录型参考源；结果可定位和导出 UTF-8 清单，但清理计划候选为空。

## 线程与性能

目录遍历、JPEG 解码与回收站操作运行在 Tauri 后台阻塞线程池，不占用 UI 线程。照片浏览按逻辑照片一次性返回轻量元数据；目录树、子目录范围和四类数量从这份索引在内存中派生，切换子目录不会重复遍历磁盘。网格缩略图只在进入可视区时请求，单张预览则在索引完成后通过 3 路受控队列全部预生成并在 WebView 中提前解码。所有请求按源路径、大小、修改时间、索引批次和目标尺寸共享内存 URL，并复用磁盘缓存，根目录切换或刷新时统一释放。参考文件先构建哈希索引，因此匹配复杂度约为 `O(JPG + RAW)`，而不是对每个 RAW 重新扫描一次参考目录。

评分数据库通过进程内互斥锁串行更新，并使用同目录临时文件、同步落盘和替换写入，避免快速连续评分产生丢失更新。评分状态独立于照片索引对象，打星不会重启缩略图预加载。

评分同步计划存放于进程内且执行后立即消费。每个目标都带生成计划时的存在状态、大小与修改时间快照；写入前重新校验，避免扫描后被外部程序修改。XMP 与 JPEG 更新均使用目标同目录临时文件、落盘同步和替换，单个照片组失败不会阻断其他组。

结果按“待清理优先、相对路径排序”返回。当前版本一次性返回内存列表，适合常规摄影目录；达到数十万文件时再引入批量事件和虚拟列表，不提前增加复杂度。

## 平台构建矩阵

| 目标 | Runner | 产物 |
|---|---|---|
| Windows x64 | `windows-2025-vs2026` | NSIS `.exe`、MSI `.msi` |
| macOS Apple Silicon | `macos-15` | `.app`、`.dmg` |
| macOS Intel | `macos-15-intel` | `.app`、`.dmg` |

构建机不是应用服务器。FramePair 是本地桌面软件，安装后直接访问用户选择的本地目录，不需要部署后端服务或上传照片。

## 验收标准

- 扫描操作对文件系统零写入。
- 12 种 RAW 格式、普通/双扩展 XMP、清单和 XMP 星级来源均有自动化覆盖。
- 未确认前不调用回收站 API。
- 路径穿越、目录嵌套、符号链接隔离目录、恢复覆盖、非白名单扩展名和已变化文件均被拒绝。
- 反向审计无法生成可执行清理候选。
- Windows 与 macOS 安装包由对应系统 runner 原生构建。
- 关键流程支持键盘、可见焦点、系统深浅色和 reduced motion。
- JPG/RAW 同名文件只生成一个逻辑照片条目，隔离区和无关文件不会进入照片索引。
- 缩略图最长边有上限、正确应用 EXIF 方向、使用唯一临时文件原子写入缓存，并拒绝路径穿越和 RAW 伪装预览请求。
- 评分只接受所选根目录内真实存在的 JPG/RAW，0 星删除记录，损坏或超限的评分数据库不会被静默覆盖。
- 手动评分同步只能消费后端生成的一次性只读计划；旧计划、路径越界、符号链接、重复 XMP、损坏元数据和变化后的目标必须拒绝。
- RAW 原文件在评分同步中保持只读；JPG 写入默认关闭并要求二次确认，写入后 EXIF、非 XMP APP 段和图像扫描数据保持不变。
- 自动同步必须先成功保存 FramePair 评分；失败只增加可重试待处理项，不回滚本地评分，也不授予任何文件移动或清理权限。
- 外部编辑器只能来自后端重新发现的系统默认项或标准安装目录中的 Photoshop/Lightroom，前端不能提交任意可执行文件路径。
- 子目录范围必须按路径分段匹配，`2026` 不能误包含 `20260`；配对筛选必须同时存在 JPG 与 RAW，零数量分类不可进入空白结果。
