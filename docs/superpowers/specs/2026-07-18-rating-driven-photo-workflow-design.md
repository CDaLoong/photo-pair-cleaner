# FramePair 评分驱动照片处理工作流设计

**状态：** 已确认
**日期：** 2026-07-18
**范围：** 配对清理模块内的评分同步、评分整理与评分清理

## 1. 背景

FramePair 当前包含两个主要能力：

- 照片浏览：按照片组预览 JPG/RAW，并在 FramePair 本地保存 0-5 星评分。
- 配对清理：根据 JPG 目录、文件清单或 XMP 星级参考源，扫描并处理未配对 RAW。

现有评分属于逻辑照片组。同目录、同文件名但扩展名不同的 JPG 与 RAW 共用一个 FramePair 评分，但该评分默认不写入 JPG 元数据或 RAW XMP。现有配对清理执行层只处理 RAW 和伴随 XMP，支持系统回收站与 FramePair 隔离区。

本设计将“配对清理”升级为规则驱动的照片处理工作台，在保留现有配对清理能力的基础上增加：

1. 手动或自动同步评分元数据。
2. 按评分将照片组复制或移动到用户指定目录。
3. 按评分生成待清理计划，并由用户在执行前选择隔离区或系统回收站。

## 2. 目标

- 保持一个清晰入口，不增加碎片化的左侧功能模块。
- 将 JPG、RAW、XMP 视为可配置但默认不可拆散的照片组。
- 允许用户按评分、格式和目录自定义整理规则。
- 所有移动、复制和清理操作必须先生成只读计划，再复核并确认。
- 自动模式只允许同步评分，绝不自动移动、复制或清理文件。
- 复用并扩展现有隔离区、操作日志、文件快照和恢复能力。
- 永远不静默覆盖文件，不把规则冲突转化为隐式执行顺序。

## 3. 非目标

- 不提供无人值守的自动移动、自动复制或自动删除。
- 不修改 RAW 原文件内容。
- 不直接读写 Lightroom `.lrcat` 目录数据库。
- 不在第一版加入 AI 评分、相似照片聚类或重复照片识别。
- 不允许用自动重命名绕过目标文件冲突。
- 不将 FramePair 配置、评分数据库或操作历史写入用户照片目录。

## 4. 已确认的产品决策

1. 照片组默认包含 JPG、RAW、XMP；每条规则可以自定义需要处理的格式。
2. 评分整理规则支持复制或移动，默认操作为移动。
3. 目标目录完全由用户选择，用户可以在系统目录选择器中创建新文件夹。
4. 每条规则可以选择保留原相对目录结构或平铺，默认保留原结构。
5. 评分规则只把照片组标记为待清理；最终执行时统一选择隔离区或系统回收站。
6. 评分来源冲突支持 FramePair 优先、外部评分优先、取较高评分；默认不覆盖并提示。
7. 评分同步可以和整理操作并存，但每个照片组最多只能有一个最终文件操作。
8. 自动同步只更新评分元数据，明确不包含复制、移动或清理。
9. RAW 评分只写入同名 XMP；JPG 元数据写入是默认关闭的高级选项。

## 5. 信息架构

左侧继续保留“配对清理”模块。模块内部第一步增加任务类型选择：

### 5.1 配对清理

保留现有任务：

- 清理无 JPG 的 RAW。
- 检查无 RAW 的 JPG。

现有 JPG 目录、UTF-8 文件清单和 XMP 星级参考源继续可用。

### 5.2 评分同步

用于批量手动同步评分，并配置自动同步偏好：

- 选择照片根目录。
- 选择同步范围和目标。
- 选择冲突策略。
- 生成只读同步计划。
- 复核后执行。

### 5.3 评分整理与清理

用于创建评分规则并处理文件：

- 选择照片根目录。
- 配置评分规则。
- 可选同时同步评分。
- 生成只读文件操作计划。
- 复核移动、复制和待清理照片组。
- 最终确认后执行。

### 5.4 统一三阶段流程

所有任务共享：

```text
配置任务 -> 复核计划 -> 安全执行
```

顶部流程文案由现有“选择目录 / 复核结果 / 安全执行”调整为以上通用表述。

## 6. 照片组模型

预览与清理模块必须共享同一套照片组索引，避免两套匹配逻辑产生不同结果。

```ts
interface PhotoGroupSnapshot {
  id: string;
  root: string;
  relativeStem: string;
  rating: RatingState;
  members: PhotoMemberSnapshot[];
}

interface PhotoMemberSnapshot {
  kind: "jpeg" | "raw" | "xmp";
  relativePath: string;
  sizeBytes: number;
  modifiedMs: number;
}
```

照片组 ID 使用相对于根目录的不带扩展名路径，并遵循任务的大小写匹配设置。照片组成员按路径稳定排序。

多个 JPG、多个 RAW 或多个可匹配 XMP 同时归入一个照片组时，索引必须保留全部成员，并将有歧义的元数据目标标记为冲突。

## 7. 评分状态与同步

### 7.1 评分来源

```ts
interface RatingState {
  framePair: number;
  jpegMetadata: number | null;
  rawXmp: number | null;
  resolved: number;
  conflict: boolean;
}
```

- FramePair 评分范围为 0-5，0 表示未评分。
- 外部 XMP 的 `-1` 拒绝标记在第一版显示为不受支持的外部状态，并进入冲突列表；不自动转换为 0 星。
- `resolved` 是当前任务按照用户冲突策略计算出的工作评分。
- 默认策略下，只要非空评分来源不同就标记冲突，不计算可执行结果。

### 7.2 手动同步范围

照片浏览模块可以发起：

- 当前照片。
- 当前目录。
- 当前筛选结果。
- 整个照片根目录。

配对清理中的“评分同步”任务支持当前照片根目录以及评分条件范围。两处使用同一后端计划接口。

### 7.3 自动同步

自动同步设置在照片浏览和评分同步任务中共享：

- 手动同步。
- 自动同步评分。

自动同步只在 FramePair 评分保存成功后运行，只更新用户启用的元数据目标。失败不会回滚 FramePair 内部评分；失败项显示“同步待处理”，可以手动重试。

界面固定显示：

> 自动同步只更新评分元数据，不会复制、移动或清理照片。

### 7.4 同步目标

- RAW：创建或更新同名 XMP，不修改 RAW 原文件。
- JPG：可选写入 JPG 内嵌 XMP，默认关闭，并要求用户首次启用时明确确认。
- 用户可以选择只同步 RAW XMP、只同步 JPG 元数据或同时同步两者。

RAW 同时存在 `photo.xmp` 与 `photo.RAW.xmp` 时视为文件冲突，不选择其一覆盖。新建 RAW 侧车文件使用 `photo.xmp` 命名。

### 7.5 冲突策略

- 不覆盖并提示，默认。
- FramePair 评分优先。
- 外部元数据优先。
- 取较高评分。

手动同步在计划中列出冲突。自动同步只暂停冲突照片组，其他照片组继续处理。

### 7.6 元数据写入安全

- XMP 必须通过 XML 解析器更新，保留已有非评分元数据。
- XMP 损坏、包含多个 Rating 或命名有歧义时拒绝写入。
- JPG 必须通过结构化 JPEG 段处理更新 XMP，保留像素数据、EXIF 和其他应用段。
- 所有元数据写入使用同目录临时文件，完整写入、同步并重新解析验证后原子替换。
- 符号链接、超出照片根目录、非常规文件和扫描后发生变化的文件拒绝处理。

## 8. 评分规则编辑器

规则按用户排序显示，但排序不承担冲突消解职责。

```ts
interface RatingRule {
  id: string;
  name: string;
  enabled: boolean;
  condition: RatingCondition;
  memberScope: Array<"jpeg" | "raw" | "xmp">;
  action: "keep" | "copy" | "move" | "cleanup";
  destination?: string;
  preserveRelativePath: boolean;
}
```

### 8.1 评分条件

- 未评分。
- 等于某星级。
- 高于或等于某星级。
- 低于或等于某星级。
- 指定闭区间。

条件只接受 FramePair 支持的 0-5 星工作评分。

### 8.2 处理格式

- 整个照片组，默认。
- 仅 JPG。
- 仅 RAW。
- 用户自定义 JPG、RAW、XMP 组合。

规则指定的某种格式不存在时，只跳过缺失格式；现有成员仍进入计划，并在照片组详情中明确显示缺失项。

### 8.3 最终文件操作

- 保留。
- 复制。
- 移动，默认。
- 待清理。

复制和移动必须选择目标目录。目录选择器允许用户创建文件夹，FramePair 不强制创建固定星级目录。

### 8.4 目录结构

- 保留源目录下的相对结构，默认。
- 平铺到规则目标目录。

任何目标路径已存在时都暂停，不覆盖、不自动重命名。目标目录与源目录相同、目标位于源目录内部或源目录位于目标目录内部时拒绝配置。

### 8.5 规则冲突

评分同步是可叠加动作。一个照片组只能有一个最终文件操作。

如果多条启用规则为同一照片组产生不同或重复的最终文件操作，该照片组标记为规则冲突并禁止执行。系统不采用“第一条规则胜出”或“全部依次执行”。

### 8.6 模板

提供可编辑模板：

- 精选归档：4 星以上移动到用户目录。
- 低分清理：2 星以下进入待清理计划。
- 保留全部备份：按评分复制到用户目录。
- 完全自定义：空规则列表。

模板只负责填充规则，不创建目录、不执行扫描。

## 9. 执行计划

```ts
interface PlannedPhotoAction {
  groupId: string;
  rating: number;
  matchedRuleIds: string[];
  syncActions: RatingSyncAction[];
  terminalAction: KeepAction | CopyAction | MoveAction | CleanupAction;
  conflicts: PlanConflict[];
}
```

计划由后端生成并绑定：

- 计划 ID。
- 根目录规范路径。
- 规则完整快照。
- 同步偏好快照。
- 每个文件的路径、大小和修改时间。
- 明确的源路径与目标路径。

前端只能取消选择可执行照片组，不能修改路径或动作。修改规则或目录必须返回配置阶段并重新扫描。

## 10. 计划复核界面

### 10.1 汇总

显示：

- 同步、移动、复制、待清理照片组数量。
- JPG、RAW、XMP 文件数量。
- 规则冲突、文件冲突、扫描后变化和跳过数量。
- 复制预计新增空间、清理预计释放空间。

### 10.2 列表

每行代表一个照片组，显示：

- 相对名称。
- 工作评分与各评分来源。
- 命中规则。
- 文件组成。
- 最终操作。
- 执行状态或冲突原因。

照片组可以展开查看每个成员的源路径、目标路径、大小和修改时间。

### 10.3 筛选

- 全部。
- 同步。
- 移动。
- 复制。
- 待清理。
- 冲突。
- 跳过。

冲突项不可勾选执行。用户必须修改规则、目录或冲突策略并重新生成计划。

## 11. 安全执行

### 11.1 通用预检

执行前重新校验全部选中照片组：

- 根目录和计划 ID 匹配。
- 文件仍存在且未替换为符号链接。
- 文件大小和修改时间与扫描快照一致。
- 所有目标父目录可信且位于允许范围。
- 所有目标路径仍未被占用。

单个照片组预检失败不影响其他组，但该组不执行任何成员操作。

### 11.2 复制

- 先把组内成员复制到目标目录中的临时文件。
- 校验大小和内容摘要后再完成目标文件。
- 全组成功后记录操作完成。
- 任意成员失败时删除本次生成的临时文件和未修改副本。

### 11.3 移动

- 同一文件系统优先使用原子重命名。
- 跨文件系统采用复制、校验、提交目标、再删除源文件。
- 全组源文件删除前必须确保全部目标文件已校验。
- 删除源文件阶段失败时进入部分完成状态，并保留可恢复操作记录；不得把该组报告为成功。

### 11.4 评分同步顺序

- 单独评分同步任务直接在原位置写入元数据。
- 移动任务在文件到达最终位置后同步目标文件元数据。
- 复制任务默认同步新副本；只有用户明确选择时才同时同步源文件。
- 待清理任务只有用户明确启用“清理前同步评分”时才更新元数据。

### 11.5 清理

评分规则只生成待清理动作。最终确认窗口统一选择：

- FramePair 隔离区，默认。
- 系统回收站。

确认窗口展示照片组数量、文件组成、空间占用、命中规则和实际路径预览，并要求明确确认复选框。

## 12. 操作历史与恢复

历史记录保存任务、规则、文件和结果快照。

### 12.1 移动恢复

将目标文件恢复到原路径。原路径已被占用、目标文件已变化或成员缺失时暂停该照片组恢复。

### 12.2 复制撤销

仅删除本次创建且自执行后未发生变化的副本。任何变化都会阻止撤销该文件。

### 12.3 隔离恢复

复用并扩展现有 FramePair 隔离区，支持完整照片组和任意成员组合，恢复不覆盖已有文件。

### 12.4 系统回收站

提供打开系统回收站和查看操作日志，不承诺应用内直接恢复。

### 12.5 评分同步重试

保存同步前评分、目标评分、目标文件与错误原因。失败项可以重新生成同步计划，不直接重放过期写入。

## 13. 持久化

- FramePair 评分继续使用版本化评分数据库。
- 评分规则保存在应用数据目录，支持导入和导出 JSON。
- 同步模式、目标和冲突策略保存在版本化应用设置中。
- 操作历史使用不可变任务清单保存，不仅依赖 JSONL 摘要日志。
- 用户照片目录只写入用户确认的 XMP 或文件操作结果。

规则导入必须校验版本、评分范围、动作类型和目标路径，不接受未知动作或绝对源文件路径。

## 14. 前后端边界

### 14.1 后端模块

- `photo_groups.rs`：照片组索引与成员歧义检测。
- `rating_sync.rs`：评分读取、冲突计算和安全元数据写入。
- `rating_rules.rs`：规则校验和动作计算。
- `operation_plan.rs`：计划生成、快照绑定和执行授权。
- `file_organizer.rs`：复制、移动、目标校验和组级回滚。
- `operation_history.rs`：任务清单、恢复和撤销校验。
- `quarantine.rs`：隔离区移动与恢复。

`lib.rs` 只保留 Tauri 命令装配和共享状态注册。

### 14.2 前端组件

- `TaskTypeSelector`：任务类型选择。
- `PairCleanupSetup`：现有配对清理配置。
- `RatingSyncSetup`：同步范围、目标和冲突策略。
- `RatingRuleEditor`：评分规则编辑。
- `OperationPlanReview`：统一计划复核。
- `OperationConfirmDialog`：按动作生成最终确认内容。
- `OperationHistory`：结果、恢复、撤销和重试。

`CleanupModule.tsx` 只协调阶段状态和 Tauri 调用，不继续承载全部表单与结果逻辑。

## 15. 错误处理

- 配置错误在扫描前显示，禁止生成计划。
- 规则冲突和文件冲突在计划中逐组显示。
- 扫描后变化在执行预检时逐组阻止。
- 单组失败不停止其他独立照片组，但最终回执必须区分成功、失败、部分完成和跳过。
- 自动同步失败使用非阻断通知和持久待处理状态。
- 所有错误使用中文可操作文案，包含照片组、路径和下一步处理方式。

## 16. 分阶段交付

阶段按顺序实施，不并行展开。

本文件是跨阶段总规格，不对应一个一次性巨型实施计划。每个阶段必须单独编写实施计划、完成测试和桌面端验收并提交；前一阶段通过用户验收后，才能开始下一阶段。第一份实施计划只覆盖阶段一。

### 阶段一：共享照片组与评分状态（已完成）

- 提取共享照片组索引。
- 读取 FramePair、RAW XMP 和 JPG 元数据评分。
- 保持现有预览和配对清理行为不变。

### 阶段二：评分同步（已完成）

- 手动同步计划。
- 自动同步设置。
- 冲突策略。
- RAW XMP 写入。
- 默认关闭的 JPG 元数据写入。

实现边界：FramePair 评分始终先保存；RAW 原文件永不写入；RAW 评分只更新同名 XMP；JPG 写入默认关闭并要求明确确认。手动同步消费带文件快照的一次性只读计划，自动同步失败进入待处理状态，不回滚 FramePair 评分，也不触发任何文件操作。

### 阶段三：规则编辑器与只读计划（已完成）

- 任务类型选择。
- 评分规则编辑与模板。
- 规则校验与冲突检测。
- 只读模拟计划，不执行文件操作。

实现边界：规则支持版本化持久化和 JSON 导入导出；四种模板只填充草稿；只读计划包含完整成员快照、规范目标和冲突原因。阶段三没有文件操作执行命令，不会创建目标目录、移动、复制、隔离或送入回收站。

阶段四及后续的真实复制、移动、隔离和回收站清理尚未实现，不能由评分同步或阶段三计划接口授权。

### 阶段四：复制与移动

- 目标目录校验。
- 保留结构和平铺。
- 同盘与跨盘执行。

## 18. 验收标准

- 用户可以在配对清理模块选择三种任务类型。
- 自动同步设置明确且只能更新评分元数据。
- 手动同步能够预览范围、目标和冲突后再执行。
- 用户可以创建自定义评分规则并选择格式、动作、目录和目录结构。
- 一个照片组不会执行多个最终文件操作。
- 所有移动、复制和清理都先生成不可变计划并完成最终确认。
- 目标冲突、规则冲突和扫描后变化不会被静默忽略。
- 默认移动、默认保留相对目录结构、默认完整照片组、默认隔离区。
- RAW 原文件永不修改，JPG 元数据写入默认关闭。
- 移动、复制、隔离和评分同步都有可核对历史；可恢复动作在安全条件满足时能够恢复。
- 现有配对清理和预览评分流程不发生行为回归。
