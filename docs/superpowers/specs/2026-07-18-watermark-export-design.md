# FramePair 水印导出模块设计

**状态：** 已确认
**日期：** 2026-07-18
**范围：** FramePair 第三个功能模块“水印导出”

## 1. 背景

FramePair 当前包含两个主要模块：

- 照片浏览：索引、预览、筛选和评分 JPG/RAW 照片组。
- 配对清理：按配对关系和评分规则同步、整理或安全清理照片。

第三个模块用于把已经筛选好的 JPG 制作为可发布副本。它不仅可以在照片内部叠加文字或 Logo，也可以扩展画布、设计边框，并把相机参数、作者署名等信息放入边框。

本模块定位为“照片成片与发布导出”，不是通用平面设计软件。所有操作都只生成新副本，不修改原照片。

## 2. 调研结论

产品设计综合参考以下成熟产品和开源工具：

- [Adobe Lightroom Classic Watermark Editor](https://helpx.adobe.com/uk/lightroom-classic/help/using-watermark-editor.html)：导出阶段应用文字或图形水印，支持九宫格定位、缩放、透明度、边距和预设。
- [Capture One Watermark Tool](https://support.captureone.com/hc/en-us/articles/360021063278-Watermark-tool)：水印属于导出配方，支持实时校样、EXIF 变量、系统字体和位置调整。
- [darktable watermark](https://docs.darktable.org/usermanual/development/en/module-reference/processing-modules/watermark/) 与 [framing](https://docs.darktable.org/usermanual/development/en/module-reference/processing-modules/framing/)：把水印和边框作为独立渲染阶段，通过处理顺序决定水印锚定照片还是画布。
- [digiKam Batch Queue Manager](https://docs.digikam.org/en/batch_queue.html)：面向批量工作流保存工具配置，水印支持文字、图片、相对尺寸、边距和重复排列。
- [Copicseal](https://github.com/copicseal/copicseal)：开源 EXIF 边框水印工具，强调所见即所得、模板和批量生成。
- [边框水印大师](https://apps.apple.com/cn/app/%E8%BE%B9%E6%A1%86%E6%B0%B4%E5%8D%B0-%E8%BE%B9%E6%A1%86%E6%B0%B4%E5%8D%B0%E7%9B%B8%E6%9C%BA%E5%A4%A7%E5%B8%88/id6480434136) 与 [光影印记](https://mark.lasfuture.com/)：面向国内摄影用户，突出 EXIF、相机与镜头信息、边框模板和自由排版。

由此确定 FramePair 的差异化方向：直接承接照片浏览中的当前照片、目录或筛选结果；用结构化图层和漂亮边框完成批量发布导出，同时保持本地处理和原图安全。

## 3. 目标

- 新增与“照片浏览”“配对清理”并列的第三个模块“水印导出”。
- 只读取 JPG/JPEG，并生成 JPEG 或 PNG 副本。
- 支持照片内水印、扩展边框水印和完整画布水印。
- 支持文字、Logo/图片和 EXIF 动态文字图层。
- 提供足够美观的边框背景与装饰能力，同时保持结构化编辑器边界。
- 支持单张实时预览、批量照片检查和横版/竖版/方形布局变体。
- 支持内置模板、本地用户模板及可移植的 JSON 导入导出。
- 预览与最终导出使用同一渲染模型。
- 永远不修改 JPG 原图、RAW、XMP 或评分状态。

## 4. 非目标

- 不支持直接为 RAW 照片生成水印。
- 不修改源 JPG 的像素或元数据。
- 不支持 WebP、AVIF、视频或动图导出。
- 不提供贴纸市场、自由绘画、任意矢量编辑或完整 Canva 类设计能力。
- 不提供 AI 排版、AI 抠图或生成式背景。
- 不提供社区、收藏、账户、云模板或云同步。
- 不直接发布到社交平台。
- 首版不支持一次任务生成多套不同输出配方。

## 5. 已确认的产品决策

1. 只有 JPG/JPEG 可以进入渲染队列；JPG+RAW 照片组只使用 JPG，RAW-only 明确标记为不支持并跳过。
2. 支持从水印模块选择目录或拖入 JPG，也支持照片浏览发送当前照片、当前目录或当前筛选结果。
3. 从照片浏览发送的是列表快照，后续筛选变化不会静默改变任务。
4. 编辑器采用三栏工作台：左侧照片与模板，中间实时画布，右侧属性，底部胶片栏。
5. 图层编辑采用结构化模型，不采用固定模板向导或通用自由设计画布。
6. 边框支持纯色、取样色、线性/径向渐变、照片模糊延展、自定义背景图片或纹理。
7. 模板包含横版、竖版和方形三套可微调布局变体。
8. 模板提供精选内置模板和本地用户模板；首版不加入社区与云同步。
9. 输出元数据由用户选择，默认使用隐私模式。
10. 输出格式只支持 JPEG 和 PNG。

## 6. 信息架构

### 6.1 应用导航

现有 `AppModule` 从 `preview | cleanup` 扩展为：

```ts
type AppModule = "preview" | "cleanup" | "watermark";
```

左侧主导航新增：

- 水印导出
- 副标题：边框、署名与发布副本

水印模块使用独立状态，不把编辑器状态塞入照片浏览或配对清理组件。照片浏览只通过明确的“发送到水印导出”命令传递源快照。

### 6.2 三栏工作台

顶部工具栏：

- 撤销、重做。
- 原图/效果前后对比。
- 画布缩放与适应窗口。
- 保存为模板。
- 导出。

左侧面板：

- 照片：显示当前任务中的 JPG、状态和警告。
- 内置模板：只读，可应用或另存。
- 我的模板：新建、复制、重命名、删除、导入和导出。

中间画布：

- 显示当前照片的真实布局效果。
- 支持选中、拖动、缩放、旋转和对齐吸附。
- 显示照片区域、边框区域和完整画布区域的边界。
- 支持隐藏所有面板进入沉浸预览。

右侧属性面板：

- 图层：图层列表、可见性、锁定、复制、删除和层级。
- 属性：当前图层的文字、图片、EXIF、位置和样式。
- 边框：尺寸、背景、照片位置、圆角、描边和阴影。
- 输出：格式、尺寸、质量、色彩空间、元数据、目录和命名。

底部胶片栏：

- 切换当前照片。
- 选中项始终自动滚动到可见区域。
- 标记横版、竖版、方形、缺失 EXIF、渲染失败和已检查状态。
- 后台预加载任务内全部缩略图；完整编辑预览优先缓存当前项和前后邻近项，避免一次性渲染全部大图占满内存。

左右面板均可独立折叠，并沿用照片浏览已有的折叠交互。

## 7. 来源与任务快照

### 7.1 来源方式

水印模块支持：

- 选择单个目录，并复用照片浏览的目录树浏览子目录。
- 将目录或 JPG/JPEG 文件拖入工作区。
- 从照片浏览发送当前照片。
- 从照片浏览发送当前目录。
- 从照片浏览发送当前筛选结果。

### 7.2 JPG 规则

- 扩展名大小写不敏感，只接受 `.jpg` 和 `.jpeg`。
- JPG+RAW 照片组选择其 JPG 成员；若同一组存在多个 JPG，全部保留并显示为独立待导出项。
- RAW-only 项不会进入渲染队列，来源汇总中显示“已跳过 RAW-only”。
- 不读取 RAW 作为 EXIF 的备用来源；可见 EXIF 和输出元数据均来自当前 JPG。

### 7.3 快照模型

```ts
interface WatermarkSourceSnapshot {
  id: string;
  createdAt: string;
  origin: "directory" | "drop" | "preview-photo" | "preview-directory" | "preview-filter";
  rootPaths: string[];
  photos: WatermarkSourcePhoto[];
}

interface WatermarkSourcePhoto {
  id: string;
  absolutePath: string;
  relativePath: string;
  sizeBytes: number;
  modifiedMs: number;
  pixelWidth: number;
  pixelHeight: number;
  orientation: "landscape" | "portrait" | "square";
}
```

进入导出前重新检查路径、大小和修改时间。源文件变化时只阻止对应照片，并要求重新载入；其他照片仍可导出。

方向按校正 EXIF Orientation 后的像素尺寸计算。宽高比在 `0.95-1.05` 之间视为方形，其余按宽高关系归类。

## 8. 编辑数据模型

### 8.1 水印项目

```ts
interface WatermarkProject {
  schemaVersion: number;
  source: WatermarkSourceSnapshot;
  template: WatermarkTemplate;
  activePhotoId: string | null;
  photoOverrides: Record<string, PhotoPlacementOverride>;
  output: WatermarkOutputSettings;
}
```

项目只存在于当前任务状态，不作为照片目录内的伴随文件保存。切换模块时保留本次应用会话中的未导出状态；关闭存在未保存模板修改或未导出结果的任务前提示用户。

### 8.2 模板

```ts
interface WatermarkTemplate {
  schemaVersion: number;
  id: string;
  name: string;
  shared: SharedTemplateStyle;
  variants: Record<"landscape" | "portrait" | "square", LayoutVariant>;
  resources: Record<string, EmbeddedTemplateResource>;
}
```

共享内容包括：

- 文字内容。
- Logo 或图片资源。
- EXIF 字段组合与格式。
- 主色和共享样式开关。

每个方向变体可以独立保存：

- 图层位置、尺寸和旋转。
- 字号和间距。
- 四边边框尺寸。
- 最终画布比例与照片位置。
- 圆角、描边、阴影和背景效果参数。

切换照片时按方向自动选择变体。编辑共享内容会更新三套变体；编辑布局参数只更新当前变体。界面必须明确显示当前正在编辑的方向。

### 8.3 坐标体系

所有模板坐标相对于输出画布或锚定区域保存，不保存界面视口像素。位置使用 `0-1` 归一化坐标，尺寸和间距使用相对于画布短边或锚定区域的比例。

图层锚定空间：

- `photo`：随照片内容区域变化。
- `frame`：锚定上、下、左或右边框带。
- `canvas`：锚定整个最终画布。

这种模型保证同一模板应用到不同分辨率时保持比例，也保证改变边框后照片内水印不会漂移到边框。

### 8.4 图层

```ts
type WatermarkLayer = TextLayer | ExifTextLayer | ImageLayer;

interface LayerPlacement {
  anchorSpace: "photo" | "frame" | "canvas";
  frameEdge?: "top" | "right" | "bottom" | "left";
  x: number;
  y: number;
  width: number;
  rotationDeg: number;
  opacity: number;
  zIndex: number;
  visible: boolean;
  locked: boolean;
}
```

普通文字图层支持字体、字号、字重、颜色、对齐、字距、行距、描边和阴影。

EXIF 动态文字支持：

- 相机厂商与型号。
- 镜头型号。
- 焦距、等效焦距。
- 光圈、快门、ISO。
- 拍摄日期与时间。
- 作者和版权。
- 自定义静态前后缀与分隔符。

字段缺失时自动隐藏空字段，并折叠相邻分隔符。用户可以选择把缺失字段显示为自定义占位文本。

图片图层接受 PNG、JPEG 和应用支持的静态图片素材。PNG Alpha 保留。内置模板只使用具有明确再分发许可的字体和素材。

### 8.5 单张照片覆盖

批量任务默认统一应用模板。单张照片只允许覆盖照片内容本身的缩放与位置，解决主体被遮挡或构图不适配的问题。

首版不允许单张照片增加、删除或重排模板图层，也不允许创建完全不同的边框结构。清除单张覆盖后立即恢复模板默认值。

## 9. 边框与画布

每个方向变体支持：

- 上、右、下、左四边独立扩展。
- 保持自然尺寸或指定最终长宽比。
- 照片在画布中的对齐和位置。
- 照片圆角、描边、阴影。
- 纯色或从照片取样的颜色。
- 线性或径向渐变。
- 照片模糊延展。
- 自定义背景图片或纹理。
- 透明背景，仅 PNG 有效。

取样色保存取样规则和最终颜色。应用到其他照片时，用户可以选择固定模板颜色或按每张照片重新取样，默认固定模板颜色，保证批量结果一致。

当图层超出目标锚定区域或可能被裁切时，画布显示警告，但允许用户保留有意的出血效果。真正超出最终画布的内容在导出时按画布边界裁切。

## 10. 编辑交互

### 10.1 直接操作与精确输入

- 拖动图层改变位置。
- 控制点等比缩放，旋转手柄改变角度。
- 画布中心线、边缘、照片边缘和其他图层提供吸附。
- 方向键微移，组合键进行大步长微移。
- 右侧属性提供位置、尺寸、透明度、旋转和间距的数值输入。
- 删除、复制、置顶、置底、锁定和显示隐藏均进入撤销历史。

### 10.2 撤销与重做

编辑命令使用有界历史记录。切换照片不会清空历史；更换整个模板、替换来源快照或开始新任务前建立明确的历史边界。导出操作不进入编辑撤销历史。

### 10.3 前后对比

按住前后对比按钮时只显示校正方向后的原 JPG；释放后恢复完整画布效果。对比不改变当前缩放、照片选择或图层选择。

### 10.4 使用引导

首次进入水印模块显示蒙版引导：

1. 导入或接收照片。
2. 选择模板。
3. 在画布选择并调整图层。
4. 检查横版、竖版和方形布局。
5. 设置输出并导出副本。

顶部提供“使用引导”入口，可随时重新打开。引导只讲当前可操作界面，不用大段功能说明占用工作台空间。

## 11. 模板管理

### 11.1 内置模板

首版内置模板覆盖以下风格，但数量保持精选：

- 极简署名。
- 白色 EXIF 底边框。
- 深色画廊边框。
- 渐变杂志式边框。
- 照片模糊延展。
- 透明 Logo 角标。

内置模板只读。用户修改后使用“另存为我的模板”。

### 11.2 用户模板

支持：

- 新建。
- 保存和另存为。
- 复制。
- 重命名。
- 删除并确认。
- JSON 导入与导出。

用户模板保存在 Tauri 应用数据目录，不写入照片目录。

### 11.3 可移植资源

自定义 Logo、背景和纹理作为带 MIME、校验值和编码数据的资源嵌入模板 JSON。模板不保存任何待处理照片。

导入时必须验证：

- Schema 版本。
- 资源类型和大小限制：单个编码资源不超过 32 MiB，单个模板资源总量不超过 128 MiB。
- 图片能否解码。
- 解码后单边不超过 16384 像素且总像素不超过 100 MP。
- 图层引用是否完整。
- 坐标与样式数值是否在合法范围。

缺失系统字体时保留原字体名称并显示替代字体警告。内置模板使用应用随包提供且许可兼容的字体，避免跨机器变化。

## 12. 渲染架构

### 12.1 组件边界

前端负责：

- 编辑状态和命令历史。
- 模板、图层与输出配置界面。
- 源快照、胶片栏和批量状态展示。
- 把版本化渲染请求传给 Tauri。

Rust 后端按职责拆分：

- JPG/EXIF 读取与方向校正。
- 模板与资源验证。
- 画布、边框和图层渲染。
- 字体排版与文本测量。
- 元数据策略与写入。
- 预览缓存。
- 批量导出队列。

前端和 Rust 共享等价的序列化请求模型。后端不读取前端 DOM 几何，也不接受未版本化的自由 JSON。

### 12.2 渲染顺序

```text
读取 JPG 与 EXIF
-> 校正 EXIF Orientation
-> 选择横版/竖版/方形变体
-> 解析最终画布尺寸
-> 绘制背景和边框
-> 放置照片并应用圆角/描边/阴影
-> 按 zIndex 绘制文字、EXIF 和图片图层
-> 应用输出色彩与透明度规则
-> 写入目标格式支持的元数据
-> 编码到临时文件
-> 验证并原子移动到目标路径
```

图层顺序由稳定 `zIndex` 和图层 ID 决定，保证同一请求重复渲染结果一致。

### 12.3 预览一致性

实时编辑使用降采样 JPG 和较小输出画布，但调用与导出相同的布局、文本测量和合成逻辑。预览请求包含完整模板，只改变渲染分辨率。

预览缓存键至少包含：

- 源路径、大小和修改时间。
- 模板内容哈希。
- 方向变体。
- 单张照片覆盖。
- 预览尺寸。

编辑器优先渲染当前照片，并预加载前后邻近项。最终导出始终重新读取完整 JPG，不直接使用预览缓存。

## 13. 输出与元数据

### 13.1 JPEG

支持：

- 质量设置。
- 保持原尺寸或设置最长边。
- 默认不放大小于目标最长边的照片；用户可以显式允许放大。
- 色彩空间可选 sRGB，默认；或在目标编码链兼容时保留原图嵌入 ICC 配置。

JPEG 不支持透明背景。画布存在透明像素时，导出前按用户选择的填充色合成，默认白色。

### 13.2 PNG

支持：

- 无损输出。
- 保持原尺寸或设置最长边。
- 默认不放大小于目标最长边的照片；用户可以显式允许放大。
- Alpha 透明背景。

只有使用透明背景且所有底层效果允许透明时才保留 Alpha。照片模糊延展、自定义不透明背景等效果会产生不透明输出。

### 13.3 元数据策略

提供三档：

- 全部保留：尽可能复制目标格式支持的原 JPG 元数据。
- 隐私模式，默认：保留相机、镜头、曝光、拍摄时间、作者和版权；移除 GPS 与设备序列号。
- 全部移除：只保留解码和显示所必需的信息。

可见 EXIF 图层与文件内隐藏元数据策略相互独立。用户可以在边框显示相机参数，同时选择移除输出文件中的 EXIF。

输出必须更新像素尺寸并把 Orientation 写为正常方向，不能保留与新像素不匹配的旧缩略图。目标格式不支持的字段明确列为不会写入，不伪造兼容性。

### 13.4 目录与命名

- 单一来源根目录时，默认在源根目录旁使用 `FramePair-Watermarked` 目录。
- 多个来源根目录时不猜测归属，导出前必须由用户选择一个输出目录。
- 用户可以选择任意可写目录，并可在系统目录选择器中创建文件夹。
- 默认文件名为原文件名加可编辑后缀，例如 `IMG_001_FramePair.jpg`。
- 文件名预览在导出确认窗口显示。

同名策略：

- 自动追加序号，默认。
- 跳过。
- 覆盖已有输出副本。

任何情况下，规范化输出路径都不能等于任一源照片路径。覆盖已有副本时使用同目录临时文件、完整编码和验证后再原子替换。

输出目录位于输入目录内部时必须明确提示，并从当前任务来源扫描中排除，避免把新副本再次加入本次队列。

## 14. 批量导出

### 14.1 导出确认

执行前显示：

- 待处理、跳过和警告照片数。
- JPEG/PNG 格式、尺寸、质量或透明度状态。
- 输出目录和命名样例。
- 同名处理策略。
- 元数据策略。
- 预计新增磁盘空间。

存在字体替代、损坏模板资源、不可写目录或可能覆盖源文件时禁止无提示执行。

### 14.2 队列

- 受控并发，避免大图批量解码耗尽内存。
- 显示整体进度、当前文件、成功、跳过和失败数量。
- 单张失败不会中断其他照片。
- 取消只阻止尚未开始的文件；正在原子写入阶段的单文件完成后停止。
- 取消后保留已经成功生成的副本，并显示结果清单。
- 应用重启后不自动继续未完成任务。

### 14.3 结果

结果页按成功、跳过和失败分类，失败项显示具体原因并可在修复后仅重试失败项。支持在文件管理器中显示输出目录。

## 15. 错误处理

- 损坏或不受支持的 JPG：跳过并列出解码错误。
- 源文件在快照后变化：阻止该项并要求重新载入。
- EXIF 字段缺失：按图层规则隐藏或显示用户占位文本。
- 字体缺失：使用明确的替代字体并在导出前警告。
- 模板素材损坏或引用缺失：标记对应图层并阻止导出。
- 输出目录不可写：导出确认阶段阻止执行。
- 导出中磁盘空间不足：停止开始新文件，清理当前未完成临时文件，保留成功副本。
- 单张编码失败：删除该文件临时产物，记录失败并继续队列。
- 模板版本过新：拒绝导入并显示所需最低 FramePair 版本。
- 模板旧版本：通过显式迁移升级，迁移失败时保留原文件且不覆盖。

所有错误文案使用中文，包含照片名称、失败阶段和可执行的处理建议，不直接向普通用户暴露 Rust 错误栈。

## 16. 安全与隐私

- 水印渲染和模板管理全程本地完成，不上传照片、EXIF、模板或素材。
- 输入文件以只读方式打开。
- 所有输出先写临时文件，编码完成并重新打开验证后再移动到目标路径。
- 规范化并验证源路径、输出路径和模板资源路径，拒绝目录穿越和源文件覆盖。
- 不跟随来源根目录外的符号链接。
- 模板 JSON 只接受已声明资源类型，不执行脚本、不加载远程 URL。
- 自定义模板资源设置解码尺寸、文件大小和总资源量上限，避免压缩炸弹和内存耗尽。
- 内置字体、Logo、纹理和模板素材必须记录并满足再分发许可。

## 17. 测试策略

### 17.1 Rust 单元测试

- EXIF Orientation 校正和方向分类。
- 归一化坐标到输出像素的换算。
- 四边边框、固定比例和照片位置计算。
- `photo`、`frame`、`canvas` 三种锚定空间。
- EXIF 字段格式化、缺失字段与分隔符折叠。
- 文件名清理、后缀和同名策略。
- 源路径与输出路径相等或嵌套检查。
- 三档元数据策略。
- 模板 Schema 验证、资源校验和版本迁移。

### 17.2 渲染基准测试

使用固定、可再分发的 JPG 样例生成基准图，覆盖：

- 横版、竖版、方形和 EXIF 旋转照片。
- 纯色、渐变、模糊延展和透明背景。
- 中文、英文、数字与混合 EXIF 文本。
- PNG Alpha、JPEG 白底合成。
- 圆角、描边、阴影、旋转和不同锚定空间。

图像比较使用允许编码微小差异的像素容差，而不是只比较压缩文件哈希。

### 17.3 集成测试

- 从目录、拖放和照片浏览快照建立任务。
- JPG+RAW 只导出 JPG，RAW-only 被统计为跳过。
- 预览请求与完整导出使用同一模板模型。
- 批量队列的成功、跳过、失败、取消和仅重试失败项。
- 临时文件清理和覆盖已有副本的原子替换。
- 磁盘空间不足、目录只读、源文件变化和损坏素材。

### 17.4 前端测试

- 三栏展开、分别折叠和沉浸模式。
- 图层选中、锁定、显隐、排序、复制和删除。
- 撤销/重做跨照片切换仍保持正确。
- 横竖方变体切换与共享字段更新。
- 单张照片覆盖和一键清除覆盖。
- 胶片栏选中项自动滚动可见。
- 蒙版引导定位与重复打开。
- 导出确认、进度、取消和结果分类。

### 17.5 手工验收

- macOS 和 Windows 的系统字体、目录选择器和文件管理器打开行为。
- 典型、小窗口、超宽屏和系统缩放场景。
- 至少一组 100 张以上高分辨率 JPG 的内存、预览切换和取消响应。
- 使用外部查看器核对 JPEG/PNG 尺寸、透明度、色彩和元数据。

## 18. 验收标准

1. 用户可以独立选择目录或从照片浏览发送快照，RAW 不会进入渲染队列。
2. 用户可以应用内置模板，并创建文字、EXIF 和图片图层。
3. 图层可以准确锚定照片、指定边框或完整画布。
4. 用户可以制作四边不对称、带渐变或模糊延展的漂亮边框。
5. 横版、竖版和方形照片自动使用对应布局，且可分别微调。
6. 批量任务可以对单张照片调整照片缩放和位置，不破坏模板图层结构。
7. 左右面板均可折叠，胶片栏选中照片始终可见。
8. 预览布局与最终全分辨率导出在位置和比例上保持一致。
9. JPEG 和 PNG 均能按命名、尺寸、质量/透明度和元数据设置生成副本。
10. 默认不会覆盖源照片；同名、不可写、磁盘不足和源变化均有明确处理。
11. 用户模板可通过单个 JSON 文件跨机器导入，Logo 和背景不会丢失。
12. 导出失败或取消不会留下伪装成成功结果的半成品文件。

## 19. 后续扩展

以下能力不进入首版，但当前数据模型不得阻止未来增加：

- WebP 和 AVIF。
- 一次任务导出多套尺寸或社交平台配方。
- 模板社区、收藏和云同步。
- 更多形状蒙版与高级文字排版。
- 直接发送到 Lightroom Classic、Photoshop 或系统分享菜单。

任何后续扩展都必须继续遵守“只生成副本、不修改原图”和“本地优先”的产品原则。
